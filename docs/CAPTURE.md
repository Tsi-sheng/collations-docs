# Capture 数据与确认流程

| 层 | 内容与生命周期 |
|---|---|
| Original Asset | 保留输入附件原始字节及身份。裁剪或转码是一次可追踪的转换，原附件可独立取回。 |
| Raw Response | 每次识别独立保存 Provider 返回的原始内容。重试追加一次记录，即使内容相同也保留两次操作。 |
| Draft Document | 从指定响应派生标准 Markdown 与 LaTeX 草稿。用户在此校对；自动保存、重新打开和生成预览均保持草稿状态。 |
| Verified Document | 用户确认具体草稿内容后得到的不可变快照，与正式 Revision 关联。后续校对派生新草稿，再次确认才能发布新版。 |

各层按实际保存字节计算 SHA-256。转换记录关联输入和输出哈希、来源附件 ID、操作及顺序、Provider、模型标识和可获得的版本。模型版本未返回时记录未知。确认记录关联状态、所见草稿的哈希及确认生成的 Revision。来源信息由 Capture 单独维护，正文可直接使用普通 Markdown 编辑器打开。

预览读取当前草稿并在内存中渲染；复制读取选中的源文本。清理若将改变任一公式，先展示源文本差异，用户接受后写入新草稿。接受清理与确认入库是两个独立动作。确认时校验草稿哈希，发现变化则保留双方内容并展示最新差异，等待重新确认。取消、失败或重复提交同一次确认均不得多产生正式版本。

汇编按[架构规范](ARCHITECTURE.md)读取已确认内容。追踪信息应能从输出片段回到确认版本、对应草稿、识别响应和原始附件。

# Capture 回归测试设计

状态：待 Capture 实现时执行。使用自行制作的公式图片、人工转录和返回固定响应的假 Provider，在离线临时工作区运行。用预先写定的 UTF-8 公式源字节作为期望，独立计算输入附件与响应的 SHA-256。

## 公式用例

每行都执行同一流程：生成草稿和预览、复制公式源码、保存并重读、确认、汇编 Markdown。预览应正确显示，暂不支持的环境应返回可读诊断，仍可取回并复制原文。逐字比较复制、重读和汇编的公式范围，包括分隔符、换行与环境名。任一静默差异或未捕获异常均失败。

| 输入公式源 | 期望及具体失败条件 |
|---|---|
| `$$f(x)$$` | 保留参数和括号。复制得到 `f` 即失败。 |
| `$$u=v\tag{A}\label{eq:a}$$` | 标签和引用键均保留。任一消失或被重命名即失败。 |
| `\begin{equation}a+b=c\end{equation}` | 以裸环境输入；异常退出或自动改写环境即失败。 |
| 两行裸 aligned 环境，见下方 | 保留对齐点、行末双反斜杠和换行。断行变化或解析异常即失败。 |

```latex
\begin{aligned}
p &= q+r \\
s &= p-r
\end{aligned}
```

## 来源与版本用例

| 输入与操作 | 期望输出 | 失败条件 |
|---|---|---|
| 同一附件连续识别两次，第二次返回不同文本 | 两条识别记录指向同一附件，各有原始响应、模型、输入输出哈希和顺序 | 首次响应被覆盖，或任一哈希与独立计算不符 |
| 对草稿提出公式清理，分别拒绝、接受，再保存并取消确认 | 拒绝保持源字节；接受只生成有差异记录的草稿。正式版本增量为零，出版请求返回诊断 | 原图或原始响应改变、生成正式版本或导出未确认文本 |
| 展示草稿 A 后修改为 B，再提交 A 的确认 | 返回差异，版本增量为零；重新确认 B 后恰有一个正式版本，其哈希等于 B。重试同一次确认仍为一个 | 旧确认生效、哈希错误或重复发布 |
| 冻结已确认版本，随后再编辑并确认新版，重建原讲义 | 原输出与冻结版本的公式源字节一致；沿映射可取回原版本、草稿、响应、附件并复核哈希 | 采用新稿、公式漂移、来源断链或历史版本无法恢复 |

这些用例验证系统能否如实保存和传递识别结果。真实模型的识别准确率需另用人工对照样本评估。

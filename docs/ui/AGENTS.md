# Collations UI 设计与截图交付约定

## 适用范围与读取顺序

适用于 Collations 的 UI 设计、交互调整及前端视觉实现任务。开始前读取仓库根 AGENTS.md、对应协议与 ADR、本文件和本次目标 Figma 画板。docs 与 desktop 的根约定必须引用本文件，使设计目录外的任务也能找到规则。用户的最新明确要求优先。

## Figma 优先

1. 先检查现有画板、组件、变量和代码入口，确认本次范围，再在 Figma 完成设计。
2. 涉及画布读写时遵守 figma-use 及相应设计技能。落实前端前，遵守 figma-design-to-code 读取设计数据和截图的流程。
3. 使用可编辑文本、图层、组件和语义变量。示例数据标明用途，原型交互与实际实现能力分别记录。
4. 完成设计并取得本次截图后再实施相应视觉改动。截图或设计读取失败时，继续可独立推进的文档、诊断与验证，明确剩余阻塞。

## 默认编写界面保持轻量

- 默认展示文件树、标签、编辑器、预览切换和保存状态。编辑器与预览可分栏。
- 大纲、反链、文档信息按需打开，右侧辅助面板默认收起。展开后的五区比例作为参考，收起后空间交给写作区。
- 左上角工作区／模块菜单提供独立任务视图入口。版本、汇编出版、文献、资料采集在相应视图中组织。
- 扫描、索引重建和备份进入工作区维护菜单。有待处理冲突或恢复草稿时显示可操作提示。
- 未实现模块在规划文档中记录，产品入口依实际能力展示。
- 模块、主题和布局切换须保留标签、未保存内容、光标、选区、滚动和撤销历史。

## 完成条件

每次 UI 任务交付至少附一张本次实际修改后的 Figma 画板截图，并给出文件及节点链接。先检查截图中的文本裁切、溢出、层级、对比度和状态可辨性，修复后使用新截图交付。

最终回复优先直接展示截图，同时说明本次改动与尚未验证项。涉及多个独立界面时用清晰总览或多图覆盖主要变化。主题、窄窗或状态专项任务优先展示相应画板。

任务包含前端实现时，另外展示实际程序截图并标注来源和验证环境。Figma 截图与程序截图分别记录。

## 资产与记录

将截图保存到本目录 assets 下，命名为 YYYY-MM-DD-主题-画板或状态.png。配套记录包含截图来源、Figma 文件键、节点 ID、带时区的截图时间、相关提交、图片相对路径及 SHA-256。设计截图关联文档基线，程序截图关联实际构建提交。

图片须可持久访问。最终回复使用已返回的本地绝对路径或持久图片地址直接展示，另外提供 Figma 节点链接。临时下载地址仅用于取回图片，不能充当长期存档。

## 失败与恢复

画布或截图接口失败时记录操作、时间、具体错误及已执行的恢复尝试。仅对明确可恢复的问题重试，避免重复建文件和重复改画板。

截图缺失或无法视觉检查时，标为「截图验收未完成」。历史截图可以用于对照，不能证明本次修改结果。仅在实际写入和回读确认后报告 Figma 已更新。

## 工程约束

原始 Markdown 字节、BOM、换行、未知元数据、Manifest 身份、安全保存和离线能力遵守既有协议。持久协议变更附 ADR、版本、迁移样例和恢复测试。Windows 发布执行对应回归，真人输入法、系统缩放和性能测试据实记录。

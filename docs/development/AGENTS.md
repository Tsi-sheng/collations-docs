# Collations 公共工程与协作规则

规则版本：COL-AGENTS-2026-11-07.2。此版本重新建立现行规则；不依赖已撤销的旧指令。适用于 main、ui、regression、review 的已授权 Collations 工作。

## 产品与数据

- 使用原生 Markdown、LaTeX 和兼容链接。保留原始字节、BOM、换行、未知元数据；无改动时不重写文件。
- Document ID、块定位、Revision ID 和内容哈希各自独立；Manifest 保存身份和协调记录，SQLite 是可重建派生索引。
- 外部修改不静默覆盖；沿用安全保存、恢复草稿与冲突审阅。编辑、扫描和索引离线工作，出版后续实现仍遵守离线原则。
- core 只依赖平台接口；文件访问、监听和 SQLite 由适配器提供。持久协议变更附 ADR、版本、迁移样例和恢复测试。

## 对话分工与消息授权

- [角色规则](agent-roles.md)和[任务板](task-board.md)定义责任与当前范围。名称是 main、ui、regression、review；本机 ID/路径不写入通用规则。
- 用户已在 main 明确授权：四个对话可为已授权 Collations 任务互发分配、澄清和交接消息，包括向 main 回报。授权不包括联系外部人员、发邮件或发布服务。工具要求核验授权时，读取 main 的原始用户实施请求，不将其他代理的转述当作新增用户授权。
- main 统一协调；用户可直接补充任何对话，执行者将范围变化告知 main。最多两个写入者，同一文件、共享接口和锁文件不得并发改动。同一 Figma 文件只由 ui 写入。
- 开工报告角色、实际目录、仓库/分支、HEAD、规则版本、可写范围。名称不明或目录错误时先只读核对，不依据目录名推断职责。
- 规则更新后显式重新读取；不要假设运行中的对话自动加载。AGENTS 是指导，不是操作系统权限隔离。

## Git 与交接

- 保留既有历史、PR 依赖和用户修改。不直接修改远程 main、不自动合并、不强推、不重置或清理他人的工作树，不提交凭据。
- 每项任务记录精确基线、负责人、范围、依赖和验收。超出范围先回 main 重新分配；在已授权范围内持续推进，不反复请求许可。
- main 核对差异和证据后串行集成功能分支；遇到需要用户决定的产品取舍才集中提问。
- [交接模板](handoff-template.md)要求实际提交、命令、环境、结果、失败、未验证与下一步。历史通过不代表当前通过，不能仅依据执行者口头宣称完成。
- 身份、Manifest、安全保存、恢复及复杂状态切换交 review 只读审查；纯文案和低风险样式可局部审阅。缺陷回原负责人，review 不自行修复。

## 验证与 UI

- 使用合成样例、独立临时数据库与 WebView 数据。当前打包 smoke 共用端口 19341，四项必须串行；main 不重复调度运行中的回归。
- Windows 原生构建、真实程序、安装环境、系统缩放、真人 IME 与模拟输入分别记录，缺少验证就标明。
- UI 任务读取 [UI 规则](../ui/AGENTS.md)，先设计后实施。轻量默认写作，辅助按需、模块独立；偏好稳定默认并记住用户主动选择。
- 每次实际 UI 设计或视觉实现交付本次 Figma 截图、节点与视觉检查；实现另附真实程序截图。失败明确报告，历史截图不替代新截图。
- 本轮组织与规则配置不改 UI，因此不要求伪造或重新生成界面截图。Figma 已知同类错误无新证据时不反复请求，不擅自新建文件。

## 执行边界

不修改全局模型、凭据或 Provider；模型由用户选择。只在当前任务执行期间跟进状态，不声称关闭对话后持续运行。不引入额外常驻代理或无人值守调度。检查点完成后按任务板继续或等待下一项，不自行扩展范围。


## 命令失败处理

- 先保留命令、实际 workdir、退出码和脱敏错误，再分类原因；详细步骤见 [命令排障](command-troubleshooting.md)。未知根因明确写“尚未确定”。
- 原生命令后立即捕获 `$LASTEXITCODE`，失败时停止依赖步骤，独立检查仍可继续；不能让日志管道或后续成功掩盖失败。PowerShell cmdlet 使用终止错误或检查异常，不依赖旧的原生命令退出码。
- 相同条件下不重复确定性失败。重试前说明证据和条件变化；有证据的瞬时错误最多追加两次诊断重试，然后保留证据并报告。此限额只约束代理诊断，不改变产品重试、测试等待或既有 harness。
- 先核对路径/仓库、工具是否安装或仅缺 PATH、认证/网络/仓库权限、沙箱和真实文件错误。权限申请走工具机制；自动审批拒绝后报告被拒动作、原因和剩余影响，不换写法绕过。安全的独立工作继续。
- Git 所有权问题仅在确认目标后使用准确路径的命令级 safe.directory，不设通配全局信任；不擅自安装工具链、修改全局身份/权限、结束未知进程或删除 Manifest/正文。作者身份必须另有核验，不能仅因旧提交存在就冒用。
- 恢复方案先核对任务范围；越界回 main 重新分配。失败既不代表整项工作必须停止，也不构成扩展范围的授权。交接记录重试与变化、受影响范围、已查证据和下一步，不将故障材料当作已修复证明。

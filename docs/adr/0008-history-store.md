# ADR 0008：显式历史与可恢复的原始字节对象

日期：2026-11-13。状态：待审实现契约；仅文档，尚未实现、未发布新持久格式。本 ADR 不修改 Manifest v3。批准后按[实施方案](../specs/history-v0.4.md)分阶段开发和验证。

## 背景及源码依据

core 4866927 的 src/index.ts 提供 Workspace.loadManifest/files/commit 和扫描；DocumentRecord.body 是提取后的索引文本，不能作为原始历史内容。src/reconcile.ts 保存 Manifest v3 的身份、冲突和决策历史，后者不是正文 Revision 历史。

desktop 94a23f2 的 src-tauri/src/main.rs 使用工作区 scan.lock、清单对比和 SQLite 事务；src-tauri/src/editor.rs 的 checked_replace 接收 UTF-8 text，并用 ReplaceFileW 备份校验替换竞态。该接口不是通用二进制恢复器。src-tauri/src/recovery.rs 处理身份清单恢复，不应被扩展成未经审查的全工作区事务。

现有[协议](../PROTOCOL.md)约定 SHA-256 对象、revision/parent/条目、恢复前提交及顶层 revision 的 YAML。core 样例只有 documents.json 与两份讲义 YAML；未发现已发布 revision 格式或对象库。以这些约定为起点，不重用 Manifest 的 version 或 generation 表达历史版本。

## 决策

1. Document ID 是持续文档身份；块是 (Document ID, Block ID)；Revision ID 是一次显式提交的 UUID；Content Hash 是原始字节 SHA-256。两文档同哈希可共享对象，不合并身份。自动保存不创建 Revision。
2. 采用独立 HistoryStore v1。拟定 .collations/objects/sha256/<前2位>/<余62位> 存不可变原始字节，.collations/revisions/<UUID>.json 存不可变快照清单，.collations/history/head.json 存可恢复的发布指针。事务记录置于 .collations/history/transactions；不存入 SQLite，不写正文。
3. 每次用户显式提交保存完整受管来源快照，而非从父版本推算增量。文档来自 Manifest 中当前存在且身份已确认的 Markdown；作品清单是用户明确纳入的 YAML 路径；附件为上述来源解析出的工作区内本地文件依赖闭包。不自动纳入任意 YAML、缓存或其他工作区文件。清单显式声明来源范围与缺失登记，附件和作品清单无 Document ID。
4. 本阶段只接受 CommonMark/GFM/WikiLink 解析器可识别的本地引用及作品清单引用。外部 URL 记为非离线资源，不自动下载；不执行 HTML/CSS 或猜测其中依赖。存在无法冻结的资源时给诊断，不能称为可独立携带讲义。附件路径保留快照内路径；相同内容按哈希去重。
5. 发布顺序：持工作区锁初验 → 持久化准备事务（含旧HEAD或明确的首次空历史依据）→ 排他写对象/校验已有对象 → 写候选清单 → 校验全部对象 → 最终重枚举来源并重验字节/Manifest/HEAD → 刷盘记录新旧指针及清单摘要 → 原子发布HEAD。最终检查检测到变化则中止，不发布候选。HEAD是发布判定点；发布前失败留下候选和准备记录，不构成成功提交，不做GC。普通多文件读取无法获得针对外部程序的原子时点快照：版本是经两轮逐项重验的采集集合，不承诺所有文件在某一瞬间同时等于该集合，也不承诺最终检查之后的外部写入会纳入或被发现。之后的外部编辑属于工作文件下一状态。
6. 每个非首Revision同时保存parent UUID及parentManifestSha256；HEAD校验最新清单，沿该摘要链校验所有祖先后才读取旧版本。缺失或摘要不匹配拒绝读取，不能因引用对象本身合法而放行旧清单变更。内容去重以字节为准，hash/size/读取后hash校验一致才复用；损坏对象不覆盖。只要HEAD缺失且已有任何历史准备记录、候选或对象，首版一律进入只读诊断，不凭旧HEAD=null自动重试新根；准备记录不能排除首次HEAD曾发布后丢失。只能经显式恢复流程核验候选与摘要链并确认是否恢复指针，不能称为自动初始化。证据矛盾同样只读，不创建空历史掩盖丢失。HEAD已指向校验通过的新清单则视为已发布，即使成功回执/事务收尾未写完。历史读写和完整性错误不等于允许重建身份。
7. 恢复不是复制旧 documents.json。历史保留身份快照作证据；执行时按当前 Document ID 解析位置、验证当前身份，保留当前 Manifest 冲突/决策历史。首轮自动恢复要求当前相对路径与该版本路径完全相同；移动或改名时planRestore返回路径协调诊断，不写盘。历史相对引用还须按当前目录/身份校核，目标解析语义发生变化或目标被其他Document ID占用时阻止恢复。须先完成独立路径/身份协调并重新审阅，不能改写旧Markdown字节来伪装修复，不静默复活或绑定。
8. v0.4-B 首轮恢复一篇已登记且存在的文档及用户确认的相关附件。明确逐文件预览；拒绝覆盖其他文档占用路径、硬链接、重解析点、大小写碰撞及越界路径。多文档全库回滚/删除文件不在首轮范围。先创建当前受管快照的恢复前 Revision，再执行带日志的原始字节替换，索引最后重建。
9. 已有附件若会影响其他文档，预览列出受影响引用，执行需要包含该影响的明确确认；不自动扩大恢复范围。每项替换备份并核对被替换字节；新文件排他创建。失败保全目标、恢复前对象和竞争备份；未知外部写入不可自动回滚覆盖。恢复不保证操作系统级多文件原子可见性，只保证日志可解释、可恢复。
10. 不在本轮实现。格式样例、校验器、失败注入和 Windows 原始字节适配须在各实现 PR 中同时交付；本 ADR 不能替代实际恢复测试。

## 未选方案与后果

- 不直接用 Git 仓库替代产品历史：先沿用已有对象/清单约定，避免将用户身份、索引与 Git 分支语义混用。现有工程 Git 历史不动。
- 不以 SQLite 存唯一历史，不给每次自动保存生成提交。
- 完整快照清单会重复条目，但内容对象去重，读取与冻结汇编更易验证。不可达对象暂留，容量清理另立带保留策略的任务。
- 原生适配需要新增字节级存储及恢复事务；不能声称现有字符串保存已满足附件保真。全库快照不包含用户任意文件，因此不是全库备份功能。
